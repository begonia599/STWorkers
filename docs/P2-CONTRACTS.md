# P2 生成契约与缺口

日期：2026-09-08。阶段为 `P2-in-progress`，不是 P2 退出验收或发布声明。
P1 的未完成项继续保留，不因生成链路接通而自动完成。

## 本轮范围

- `POST /api/backends/chat-completions/status`：模型列表，向上游发送 `GET /models`。
  Custom 仍保留原版手填模型和跳过状态检查的行为；“跳过”不证明模型服务可用。
- `POST /api/backends/chat-completions/generate`：向上游发送 `POST /chat/completions`。
- `POST /api/backends/chat-completions/process`：返回 `{ messages }`，不调用模型或读取模型凭据。
- 原版 `openai` 与 `custom` 来源；其他专用提供商返回 `501 MODEL_SOURCE_NOT_IMPLEMENTED`。
- 普通文本消息、文本内容数组与 tool 消息；无后处理时保留消息内未知字段。
  卡片/预设/世界书装配仍在浏览器，Worker 只执行用户选定的原版提示词后处理。
- 温度、输出上限、惩罚项、top_p/top_k、stop、seed、n、数字 logit_bias、logprobs 转换。
- tools/tool_choice 原样传输；这不等于原版工具执行或插件工具调用已经验收。
- 自定义接口的 YAML 请求体合并、删除字段、自定义请求头；使用固定版 `yaml@2.8.3`。
- YAML 映射及映射列表采用原 ST 的浅合并顺序；删除支持数组、映射或单个字符串。
- 不静默吞掉非法 YAML；单项限制 16384 字符，不允许 alias，避免展开消耗和递归数据。
- 不允许 YAML 改变或删除 stream 模式，避免浏览器与上游采用不同响应协议。

## 后处理与结构化输出

- 支持空模式、merge、merge_tools、semi、semi_tools、strict、strict_tools、single，
  以及原版历史别名 claude。独立 process API 和实际生成使用同一份转换逻辑。
- 保持原版示例角色名、群成员前缀、同角色消息合并、strict 中间 system 转 user、
  user 占位、工具字段保留/去除及工具结果转 user 的顺序。
- 后处理作用于副本，不修改存储中的聊天。合并模式可能合并消息并舍弃后续消息的附加字段，
  与锁定版本一致；不能把无后处理模式的逐字段保留承诺套用到合并结果。
- 固定占位文本为原版默认 `Let's get started.`，当前不支持原 Node config.yaml 的自定义值。
- 单次最多 4096 条消息；人名及消息 name 最多 512 字符，群名最多 128 个。
  转换结果仍受 1 MiB 限制，未知模式及非文本媒体明确失败。
- JSON Schema 按原 ST 展开根 `$defs`，移除根 `$defs`/最终根 `$schema`；
  缺失引用、循环引用变 `{}`，引用节点的兄弟字段被替换。这些是原版行为，
  不是完整 JSON Schema 解析规范，也可能减弱原 schema 约束，不能误认为通用校验器。
- 外部 `$ref` 原样保留，不下载；嵌套 `$defs`/JSON Pointer 转义不增加原版以外的解析能力。
- Schema 展开最多 64 层、20000 个访问节点及保守估算的 1 MiB 大小，超出明确失败。
  这些边界不证明免费 Workers CPU 额度必然够用，仍需实际测量。
- Schema 名称要求 1-64 位字母、数字、下划线或连字符，strict 为可选布尔值。
  属性构建和 `$defs` 查询采用自有属性安全操作，避免 `__proto__`/constructor 影响原型链。
- reasoning/verbosity 使用锁定 ST 的模型表和映射，包括 min 转 minimal、固定 effort 值。
  这不是当前提供商模型可用性声明；未知模型的下拉选项按原 ST 规则处理，
  自定义服务参数仍可经 YAML 显式提供。
- 顺序对齐原版：消息后处理、Custom YAML 合并、schema/推理参数和 stop/tools 覆盖、
  Custom exclude 最后执行。仅新增网络/预算安全检查，不重新排列模板或事件。

## 原版前端

预设、宏、正则、世界书及消息排序继续由原实现执行。`openai.js` 的兼容修改包括：

1. 错误处理只捕获 JSON 解析失败，不再吞掉自己抛出的模型错误。
2. OpenAI/Custom 流在未收到 `[DONE]` 时正常关闭，明确提示回复可能不完整。
   检查在浏览器完成，不向 Worker 添加 SSE 解析或 Token 计算。
3. 连接模型失败时显示 HTTP 状态和结构化错误；安全/配置错误不能继续显示为跳过检查。
   普通模型列表不可用时仍保留 Custom 的原版 bypass，但不能据此声称模型已连接。

结束标记检查是本轮明确的兼容约束：未发送 `[DONE]` 的兼容服务会显示不完整错误，
即使它已发送 finish_reason。用户主动停止不触发该错误。
Token 仍是临时前端估算；超出提供商上下文时保留错误，不自动截断、重发或改变提示词。

## 模型地址和凭据

2026-09-10 按用户决定取消模型域名白名单。官方 OpenAI、自定义 OpenAI-compatible 服务
与反向代理均直接使用原版界面配置；完整 API base URL 可以包含 `/v1` 等路径。
不需要修改 `.dev.vars` 或部署变量；初始化工具不再生成白名单，也不再接受 `--model-origin`。
旧配置中的 `MODEL_ALLOWED_ORIGINS` 已无作用，离线预检允许其残留，不要求所有者手动迁移。
这没有新增其他原生提供商适配，也不改变浏览器插件下载或模块加载的行为。

- 正常模型地址必须是公共 HTTPS 主机名；拒绝 IP 字面量、localhost/internal/local、
  URL 内嵌用户名密码、查询参数、fragment，以及指向本站的请求。
- 唯一 HTTP 例外：入站与出站均为 HTTP `127.0.0.1`，且不是同一 origin。
  仅用于本地合成测试，不允许云端通过开关访问 HTTP 本地模型。
- 不跟随任何 3xx；用户须填写最终 URL。不会把凭据随重定向发送到另一地址。
- openai 使用其独立加密密钥；custom 使用 custom 密钥，允许无密钥服务。
  反向代理仅使用原版 proxy_password，不回退到 OpenAI 密钥。
- 支持显式 secret_id；指定项不存在时返回 404，不偷偷使用另一个活动凭据。
- 出站头从空集合建立，不转发本站 Basic 登录、Cookie、CSRF 或浏览器请求头。
  自定义 Authorization/api-key 等提供商头允许；传输、来源、代理、CF 和安全头禁止覆盖。
- 不把上游响应头、重定向地址或原始 HTTP 错误正文返还给浏览器。
  错误信息采用本地固定描述，避免上游回显提示词或凭据。
- 地址格式和 HTTPS 校验不构成 DNS 固定或 DNS 重绑定防护；所选域名及其运营者
  必须可信。浏览器插件仍是所有者信任的特权代码，真实 Workers 出站网络边界仍需云端安全验证。
- Custom YAML 请求头和原版 proxy_password 仍属于前端设置数据，不承诺像 secrets API
  一样不向浏览器暴露；优先使用原版 API Key 输入框保存模型密钥。

## 流、限制和错误

- 入站 JSON 和组装后的请求体各最多 1 MiB；单次响应最多 8 MiB。
- 流式响应不整段缓存，不在 D1/R2 暂存生成内容；最终聊天保存仍走原版流程。
- 请求最多五分钟；超时取消上游。非流式超时返回 504，已开始的流用 SSE error 报告。
- Workers 配置启用 `enable_request_signal`；监听入站断开与响应流 cancel，并取消上游。
- 非流式及尚未发送流头时保留 HTTP 400/401/403/404/413/429/5xx；
  协议错误、3xx、网络失败返回明确错误。流头发出后使用 SSE error，不能只看 HTTP 状态判断成功。
- 已发送流头后，连接中断或超出响应预算以原 ST 可识别的 error 事件结束。
- 不自动重试模型请求，避免停止后继续耗费模型额度或重复生成。
- 成功的非流式 JSON 与流中模型正文属于提供商内容，不进行提示词或敏感词清洗。
  不能把 HTTP 错误脱敏规则误解为能替不可信提供商净化模型输出。

### 2026-09-09 流式等待与取消修正

本地实测发现：仅依赖 Request.signal 和流 cancel，首包前及无后续数据的停顿流
不能保证及时关闭上游。原版 Node 参照可以关闭；Miniflare 入口和直连 workerd 均复现。
没有据此推断真实 Cloudflare 的行为，也没有修改原版前端或插件。

- 流式请求等待模型响应头最多 250 ms；超过后先返回 SSE 通道，不伪造模型回复或完成事件。
- 等待首包或完整 SSE 事件边界时，每秒可发送一条注释保活，使传输层能发现断开。
  每个分片仅检查末尾最多四个字节和跨片换行状态，不分词、不解析模型 JSON 或重组提示词。
- 不把注释插入未完整的 SSE 事件或 UTF-8 字符。原模型字节保持顺序，五分钟总超时及 8 MiB 模型正文限制保留。
- 流头之后的 HTTP 错误、重定向、非法格式和超时会变为脱敏 SSE error，不补发 `[DONE]`，
  不自动重试。Helper 普通/自定义 API 的延迟 429 都实际拒绝，而非返回成功。
- 慢流的 HTTP 状态可能已是 200，这是与原 Node 路由的明确传输差异；原版/Helper 前端读取 error 事件。
- 首包前停止及完整事件后停顿时停止在本地浏览器通过；首包前停止另通过最终构建包的
  Miniflare 入口和直连 workerd 两条 HTTP 路径。不是云端时延或模型计费停止保证。
- 非流式首包前取消、未完整 SSE 事件中途长期停顿的快速取消仍待验收；不能把当前保活外推到这些情况。

运行 `node cloudflare/scripts/check-cancellation-runtime-local.mjs` 可检查已构建 Worker 的首包前取消；
它使用临时本地 D1/R2 和随机测试凭据，结果在 `.build/cancellation-runtime/results.json`。

## 本地证据

`cloudflare/scripts/check-generation-local.mjs` 启动隔离 D1/R2 数据目录 `.wrangler/p2-test`，
使用 8790 的 Workers 与 8791 的合成 HTTP 模型；结束后关闭测试服务。
另外以随机回环端口挂载锁定版本原 ST 的真实 chat-completions 路由。
参照路由只允许随机测试凭据、指定路径及该合成模型地址，不启动完整原版服务；
配置只读受跟踪的 default/config.yaml，空密钥文件位于独立 `.build/reference-api/`。
它不启动或调用真实模型，不读取原项目私人数据，也不部署云端。

固定样例同时包含角色卡、命名预设、宏、仅提示词正则和关键词世界书：

- 实际模型消息中，预设、世界书、角色描述依次出现；角色/用户宏已替换。
- 聊天显示保留 RAWWORD，发给模型的是 REGEXWORD。
- 流式中文字符故意跨字节分片，最终回复保持完整。
- 原版 UI 发送、重新生成、停止、非流式、429 后手动重试。
- 实际上游连接断开、正常关闭却缺少结束标记，以及两种情况下的恢复。
- 重新生成不额外引入消息；首轮与重生成实际消息数组相等。
- 先检查持久化聊天快照，再使用全新手机浏览器上下文重载。
- 手机原版连接与再次发送通过；桌面 1440x1000、手机 390x844 截图已经检查。
- 原版下拉控件逐项验证 8 个当前后处理选项；另通过 API 验证 4 组 Schema/参数优先级。
- 23 份输入分别经过 Workers 和原版真实路由后，实际模型请求体逐字段相同。
- `/process` 的 9 种模式返回相同。源码函数测试覆盖 108 个固定组合和 720 个确定性组合。

截图、实际合成请求及结果写入 `cloudflare/.build/generation-browser/`。
其中 `parity.json` 保存输入及两端出站请求体，并记录原版提交。
这是同一份浏览器组装输入经过两个真实后端的对照，**不是两个独立前端的全流程/变量对照**。
安全相关请求头有意不同，不声明原始 HTTP 头或错误正文与原 ST 完全相同。
原版初始请求失败的点击处理仍会产生一次可见页面异常；测试只允许故意注入的
429 对应的精确异常，其他页面异常一律失败。

## 剩余门槛

- 更多独立前端的复杂、非幂等宏与社区变量用例；以下固定样例不是完整生态覆盖。
- 复杂社区用例和其他提供商转换，不以已实现的文本后处理代表完整多模态/提供商兼容。
- 传统 `/completions`、多模态媒体、文本到 Token ID 的 bias 接口及其他提供商路由未支持。
- 多回复 n/tool 事件的传输单测不能替代原版 swipe、工具执行、酒馆助手或 EJS 用例。
- 真实模型接口、真实 Cloudflare 取消行为、长流量与免费 CPU/内存/请求配额没有实测。
- 酒馆助手、EJS、MVU、实际社区卡、完整 P1 及 P4/P5 门槛仍未通过。

参考依据：锁定提交的 `src/endpoints/backends/chat-completions.js`、
`public/scripts/openai.js`、Cloudflare Workers Request/Streams/Compatibility Flags 官方文档，
以及 YAML 官方解析选项文档。未将原版 Node 后端导入 Worker bundle。

## 独立前端对照

`cloudflare/scripts/check-frontend-parity-local.mjs` 启动三项回环测试服务：
8792 的 Workers、8793 的完整原版 ST、8794 的合成模型。结束后全部关闭。
Wrangler 存储使用每次新建的 `.wrangler/p2-parity/<uuid>`，不接触开发预览数据。
原版由 `git archive` 从锁定提交导出 904 个受跟踪源码文件到 `.build/upstream-browser-*/source`；
没有复制工作区、私人配置、数据、忽略的扩展或原项目 node_modules。
参照使用独立新数据目录、随机 Basic 凭据、原生 CSRF，保持仅回环监听。
停用浏览器自动启动、自动模型下载、服务端插件及扩展自动更新。
原版 frontend 和 Tokenizer 没有替换或打补丁；关键文件哈希逐字节核对提交对象。

两套独立浏览器会话各自初始化并执行相同操作，15 个状态检查点、每边 7 份实际出站请求相同：

- 原生 `/setvar`、`/setglobalvar`，经真实设置和聊天 API 确认保存。
- 卡片、命名预设、宏、仅提示词正则和关键词世界书的实际模型消息一致。
- 重生成、新回复分支、左右切换恢复各分支 `extra`，原版消息编辑保留分支扩展字段。
- 8192 上下文保留合成长消息；1024 上下文剔除旧长消息并保留最近消息。
  旧长消息仍保存在聊天中，没有被截断或删除。
- 原生 `generateQuietPrompt` 与 `generateRaw` 返回相同结果，不新增/替换聊天消息；
  临时输出上限 64 发给模型后恢复为 128。Raw 不偷偷加入卡片/预设/世界书。
- 关闭旧会话，全新 390x844 手机上下文恢复变量、消息、swipes、分支字段后再次发送。
- 比较非 dry-run 的生成/消息/切换事件顺序，不拦截或改写应用事件。

边界需要明确：

- 两端各自运行计数。Workers 计数后端请求为 0；原版真实请求本地 Tokenizer。
  `results.json` 记录各自计数，不比较数值相等；样例只验证明确的保留/剔除区间，
  不证明临界 Token 附近的消息选择完全相同，更不代表提供商账单精度。
- 后台提示词面板试算受防抖及执行速度影响，dry-run 次数可能不同；
  按原版显式 dryRun 参数单独记录，不把后台次数视为实际生成事件。
- 测试中的预设 `setvar` 幂等赋值保留，回复中的 `setvar` 在本例显示时未执行，
  被纳入后续提示词后才执行。没有据此宣称所有位置的宏都只执行一次。
- 分支字段由测试通过原生客户端上下文显式写入，不是酒馆助手或 MVU 脚本。
  只比较所记录的语义字段，时间戳、计数、随机完整性 ID 等运行信息不要求相等。
- 没有测试真实插件、真实模型或云端；没有把完整 Node 服务导入部署 bundle。

证据在 `.build/frontend-parity/results.json`、`requests.json` 及两端桌面/手机截图。
启动时没有 HTTP 失败、未处理页面异常或浏览器站外请求。
