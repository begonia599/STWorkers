## 功能对照

`cloudflare/scripts/check-p3-lighthouse-local.mjs` 完成 15 个状态/观察检查点：

1. 主 InitVar 初始化，全部初始字段与卡内 YAML 相同。
2. 备用开场白及切回主开场白，保存并恢复对应 swipe 的变量。
3. 在克隆数据上调用真实 `Mvu.parseMessage` 做命令探针，验证探针不改变持久聊天状态。
4. 原版流式发送、重生成、新回复分支：好感度分别为 34、35、36。
5. 原版左右按钮恢复 35/36，而不是在当前分支上重复累计。
6. 第二轮回复后好感度 40；EJS 在发送前读取上一轮 36，条件条目出现。
7. 原版角色宏、纯宏面板、正则隐藏锚点和 assistant 历史中的更新块。
8. 世界书蓝灯探针、旧灯室正向命中、雾号 probability=0 不命中、阴性对照正文不注入。
9. 纯宏面板桌面显示与全新手机会话重载后的逐楼层取值对照。
10. 在两端导入副本中，仅切换卡已提供的两条面板正则的 disabled 开关。
11. 真实 jQuery iframe 读取当前楼层的 Mvu 数据，手机生成后好感度 41。
12. 再次全新桌面会话重载，jQuery 面板分别显示楼层值 30、36、40、41。

两端各 5 份合成模型请求体逐字段一致；模型仅返回测试规定的正文和 MVU 命令。
状态、消息、swipes 和消息变量逐项比较，两边均完成持久化和新上下文恢复。
Windows Chrome 1440x1000 和 390x844 截图已检查；jQuery iframe 未出现横向溢出。
完成对照的成功执行中，HTTP 错误、未处理页面异常、控制台错误、未授权外部请求均为 0。
最终执行 Workers 后端 Token 请求为 0，原版为 95 次，保留真实原生 Tokenizer。

另外保留了一次真实失败：运行 `7e000f07-9724-4d15-974e-dec484e609a0` 获取
`javascript-natural-sort@0.7.1/+esm` 时发生 CDN 连接 ETIMEDOUT，MVU 加载等待超时，
面板没有完成初始化。这次没有完成原版对照，不算通过；网络可用性风险不被先前成功结果消除。

这些功能断言不要求模型自己推断值。固定回复只输出显式命令，例如第二轮达到 40 时没有附加状态变更命令，
因此“状态”仍为平静；不能据此声称模型跨档规则验证成功或失败。

## 问题与行为边界

下表中的现象均在原版与 Workers 出现，不作为已确认的 Workers 专属缺陷。

| 项目 | 实测 | 对测试卡的影响 |
| --- | --- | --- |
| 动态物品新增 | `_.set('沈舲.物品栏.马灯', {...})` 没有新增键 | 原卡给模型的新增示例不能实现预期动态物品 |
| 改用 insert | 原卡的空物品栏 schema 不可扩展，单换 `_.insert` 仍不新增 | 需要同时处理初始化/schema 的可扩展约定，不能只改函数名 |
| 可扩展探针 | 仅在内存副本把物品栏节点 schema.extensible 设为 true 后，真实 `_.insert` 成功 | 是定位/修卡方向的证据，不代表原卡已经修好；没有写回聊天 |
| 删除命令 | 对内存副本预置物品后，`_.delete('沈舲.物品栏.马灯')` 成功删除 | 本 bundle 确实支持 delete；不要把前一步“未新增”误诊为“不支持删除” |
| 老值检查 | `_.set('沈舲.好感度', 999, 34)` 将实际 30 改为 34 | 卡里“老值不一致会丢弃”的引擎保证不成立 |
| 备用 InitVar | 备用开场白覆盖整份主初值，没有保留编号、状态、物品栏和值班字段 | 备用块需要完整初值，或明确接受缺字段；不是浅合并补丁 |
| 只读/范围 | 解析器可把编号改为 CHANGED，也可把好感度改为 999 | 卡内自然语言 readonly/range/check 是模型指令，不是本卡已经实现的代码校验 |
| 宏面板历史值 | 重载前各楼层为 30/36/40，重载后面板均为 40，存储仍是 30/36/40 | 显示使用最新变量，不能用这种宏面板判断历史楼层数据丢失 |
| jQuery 深色主题 | 按楼层读数正确，但透明面板默认黑字，深色背景下难以阅读 | 视觉验收未通过；iframe 的 color:inherit 不等于继承外层页面文字颜色 |

没有通过更改卡、MVU 或原版前端来隐藏上述问题。
已验证的是“这些操作的真实功能/数据结果与原版相同”，不是“这张卡的全部设计假设成立”。

## 事件与剩余门槛

保留原生和 MVU 的实际事件轨迹，并把显式 dryRun 的 GENERATION_STARTED 单列为 PREVIEW_STARTED。
部分阶段的观察者回调顺序/后台预览次数存在双环境差异，尤其是新 swipe 与异步重渲染。
本轮没有逐事件时序一致性的通过断言，不把状态一致扩大为事件完全一致；
尚未定位这些差异是调度变化、观察窗口还是适配问题。需要后续独立重复实验。

尚未验证：

- 作者完整 T/N 表、sticky/cooldown/delay 的逐轮断言及递归反向测试。
- 真实模型能否正确决定更新内容、遵循只读/范围、输出合法更新块。
- 修订卡的新开局、动态物品流程、两套面板的完整主题和交互验收。
- 角色切换、导出再导入、其他社区 MVU 脚本与长期资源回收。
- 真正的免费 Workers 部署、外网取消/网络边界及资源指标。

用户不必重新提供已经内嵌的三件套；下一份需要的资料是作者 README 中的完整 T0~T8/N1~N8 表，
以及用于可复现制卡的源包。下一轮应保留本卡原始哈希，另给明确版本的修订副本。
