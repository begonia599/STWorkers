## 立即试用

[Deploy to Cloudflare](https://deploy.workers.cloudflare.com/?url=https://github.com/begonia599/STWorkers)

在设置页使用新的仓库、Worker、D1 和 R2 名称，例如 `STWorkers-button-test`、
`stworkers-button-test`、`stworkers-button-test-db`、`stworkers-button-test-files`。
不要选择已有 `stworks-cloud-test` 的资源，也不要导入唯一的重要数据。
所有者测试时需为仓库副本换一个名称，避免与源仓库 `STWorkers` 冲突。
设置独立的至少 24 字符访问密码，保留根目录、`npm run build` 和 `npm run deploy`；
部署成功后使用 `owner` 和该密码登录。无需将模型 Key 填到部署表单。
账号新版使用原版登录页和 Cookie 会话，首次登录后可在原版账户面板改密。
`AUTH_PASSWORD` 仍用于初始化及账号恢复，`DATA_KEY` 不随改密变化。
旧实例升级先执行新增迁移，再上传 Worker；恢复和验证边界见 [账号说明](ACCOUNT-AUTH.md)。
如失败，先记录失败步骤和已遮住凭据的错误截图，不要反复新建资源或删除初始化状态。

## 目标用户流程

当前实验入口供用户按以下目标流程实测，不预先保证每一步已通过：

1. 点击项目的 Deploy to Cloudflare 按钮，登录 Cloudflare，授权自己的 GitHub/GitLab 账号。
2. 在设置页确认新仓库、Worker、D1 和私有 R2 名称，设置至少 24 个字符的独立访问密码。
3. 接受构建与部署命令，等待平台准备插件、打包、初始化和部署。
4. 打开实际分配的地址，用户名为 `owner`；使用刚设置的访问密码登录，再在原版界面配置模型。
5. 要增减预装插件时，在自己的仓库编辑 `plugins.txt`，提交到生产分支并等待一次构建部署。

这里的“一键”不表示免账号、免授权、无任何开通确认或无限免费。
平台按钮会将源仓库复制到用户的 Git 账号，不是要求用户再在手机上编译。
手机账号授权、R2 开通及可能出现的计费资料要求仍待实测；模型费用独立计算。
默认清单仍是酒馆助手和 EJS，Helper-only 是另一项已有云端实验，不改变发行默认值。

## 两条构建路线

| 路线 | 当前状态 | Cloudflare 凭据 | 插件版本锁 |
| --- | --- | --- | --- |
| GitHub Actions | 真实托管构建通过，更新已有实例尚未验证 | 手动配置仓库 Secret | 内置临时 GitHub Token 保存根目录锁文件 |
| Workers Builds 原生入口 | 仅本地原型通过，首次云端待测 | 目标是使用平台自动配置的构建授权；实际权限待测 | 根目录锁优先，新增插件的历史锁保存到 D1 |

两条路线复用 `actions-release.mjs`、清单解析、归档校验和静态打包，不维护第二套插件安装器。
原生路线不执行 Git 推送，不需要 GitHub PAT；这不等于 Cloudflare 平台不使用 Token。
不要让两个平台同时部署同一实例。普通更新和锁状态写入还没有完整的跨构建串行保护。

## 根目录入口

| 文件或命令 | 用途 |
| --- | --- |
| `wrangler.jsonc` | 原生根配置，声明 Worker、鉴权资产、D1/R2 及两项必需 secret |
| `.dev.vars.example` | 按钮设置页只要求所有者填写 `AUTH_PASSWORD` |
| `.node-version` | 固定 Node 22.14.0 |
| `package.json.cloudflare.bindings` | 密码、数据库和存储的设置说明 |
| `npm run build` | Workers Builds 中选择预装构建；普通本地环境保留原有无第三方构建 |
| `npm run build:cloud` | 显式执行预装构建；本地只下载、打包和 dry-run |
| `npm run deploy` | 仅受校验的 Workers Builds `main` 生产构建可执行初始化及上传 |
| `cloudflare/migrations/0003_deployment_state.sql` | 增量添加初始化状态和原生插件锁表，不改写用户文档 |

按钮必须指向整个仓库根目录，构建根目录也必须为根目录。
`cloudflare/` 依赖父目录的原版前端、默认资源和 Node 依赖，不是自包含模板。
根配置里的 D1 UUID 是占位符；原生部署必须读到平台预配并写回的真实 UUID。
允许平台改变资源名、账号和数据库 ID；鉴权、资产路径及其他配置变化会被保护性校验拒绝。
资源名当前限制为 3 至 47 位小写字母、数字和连字符，首字符为字母，末字符为字母或数字。

脚本要求平台提供 `WORKERS_CI`、`CI`、分支、提交、构建 UUID 及账号上下文。
暂时只支持 `main` 生产部署，拒绝本地和其他分支的原生执行。
不要伪造这些环境变量绕过保护，也不要把默认 preview upload 当成经过验证的路径。
原生构建不自动运行完整契约测试；维护者须在提交前执行测试，或先经已有 Actions 验证。

## 初始化与更新

1. 构建父进程只读 D1 的既有插件锁；子进程只接收必要运行环境，不接收平台或自定义构建秘密。
2. 从公开插件仓库下载已锁定归档，复用原编译文件；不运行插件的 npm 生命周期、构建脚本或 Git hook。
3. 检查清单、资源与私有文件排除，执行 dry-run；保存绑定到配置、源码提交及打包回执的原生回执。
4. 部署前检查目标 Worker 的绑定、访问密码 secret 名称、D1/R2 名称、表结构及用户文档数。
5. 通过 `DB` 绑定执行增量迁移，不使用写死的数据库名称。
6. 只有缺少 `DATA_KEY`、没有用户文档和初始化记录的空库，才可原子取得初始化资格。
7. 为首次实例生成 32 字节随机密钥，先通过 Cloudflare secret API 保存，再上传大体积资产。
8. 上传继承既有 secret，不传密钥文件，不自动创建或替换资源；最后再次核对绑定并保存插件锁及就绪状态。

平台按钮负责预配资源；脚本不是遇到 403/404 就自动创建替代数据库或扩大权限的工具。
已有 `DATA_KEY` 时永不生成替代值。发现有数据却缺钥、无关表或不匹配绑定时，部署停止。
访问密码是否足够长仍由运行时检查；控制面 secret 元数据只可确认名字，不能替代真实登录测试。
下载子进程移除环境秘密不是不可信代码沙箱，项目源码、依赖、维护权限和浏览器插件仍需要信任。

原生版本选择按清单中的仓库和 ref 匹配，仓库锁优先，再沿用 D1 里的既有锁。
只有尚无匹配锁的新条目才解析提交；普通重建不自动升级插件。
原生入口目前没有 Actions 的 `update_plugins` 复选框，主动升级流程尚待统一；
可指定新的明确 ref 形成新选择，但不能把修改 ref 当作已完成的更新界面。
移除条目只取消下一次预装，不删除聊天、设置或 R2；在线版本和卸载记录仍保留原优先级。
D1 插件锁保存属于部署元数据，不是用户资料备份。

## 密钥与失败恢复

**当前没有自动生成密钥的所有者导出/恢复入口，不适合存放唯一的重要数据。**
`DATA_KEY` 只写入 Worker secret，不写日志、源码、D1 明文或构建回执。
它用于解密已保存的模型凭据；登录密码不是它的替代品。
删除 Worker 后，即使 D1/R2 尚在，也不能据此恢复已经丢失的模型凭据密钥。
备份入口及真实恢复演练是公开前未关闭的门槛，不能用“平台保管了 secret”替代。

| 现象 | 当前处理 |
| --- | --- |
| 下载、哈希或 build 失败 | 不进入本项目部署步骤；平台可能已预配资源，不能声称远端什么都没有 |
| API 403/404、D1 未预配 | 保留现状，检查资源与构建授权；不自动增加权限、创建新库或改成 Global API Key |
| 迁移失败 | 不继续生成密钥和上传；迁移可能已有部分完成，需检查后重试 |
| 密钥已保存，但资产上传失败 | 保留密钥和初始化记录，下一次可继承原密钥重试 |
| 密钥创建结果不确定，且检查仍缺钥 | 保留 pending 记录并停止；不得删除记录后盲目重生成 |
| 有用户文档但缺少 `DATA_KEY` | 停止；只能找回原密钥或按尚待实现的恢复流程处理 |
| 上传后绑定检查或锁写入失败 | 明确标记上传已尝试，检查实际版本和状态；不声称已回滚或未部署 |

错误输出不包含 API 响应正文、凭据值或捕获的 Token 输出。
常规失败后的回滚、跨实例迁移与多构建竞争恢复尚未完整验收，不通过重置数据绕过失败。

## 本地证据

在完整项目根目录安装依赖后，可复现：

```powershell
npm ci --ignore-scripts
npm --prefix cloudflare ci --ignore-scripts
npm --prefix cloudflare test
npm run build:cloud
node cloudflare/node_modules/wrangler/bin/wrangler.js deploy --config wrangler.jsonc --dry-run --outdir cloudflare/.build/native/root-worker --strict --x-auto-create=false --no-x-provision
npm --prefix cloudflare run build
```

以上预装构建会访问公开插件下载站点，所有 deploy 命令都带 `--dry-run`，不上传云端。
真实原生部署命令不应在本地尝试。浏览器复现命令见 `GITHUB-ACTIONS.md`，复用同一预装资源包。
